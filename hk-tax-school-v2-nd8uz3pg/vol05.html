記帳の自動化を
「レビューできる仕組み」に育てる

起票の自動化は第3回で体験しました。第5回はその先です。AIが起票した帳簿を、AI自身に税理士の目でレビューさせる。仕訳帳のチェックと消費税区分のチェックを「型」にして、自分の実務に合わせて育てていきます。

🎯 この課題を終えると…

  • 自動記帳が「その場かぎりの体験」から、毎月同じ手順で回る型になります
  • 畠山が顧問先60社の月次で使っている仕訳帳レビューの観点（サンプル10個）をAIに実行させられます
  • 消費税区分の点検観点（サンプル6個）で、少額特例・海外SaaS・軽減税率などの誤りに気づけるようになります
  • ルール表とレビュー観点に自分の実務ならではの1行を足して、コミュニティに共有できます
  • 最後に確認テスト（AIが先生役・70点以上で合格）を受け、恩送りメモを投稿すると修了です🏅
⏱ 目安：合計 約80〜100分　／　💪 難易度：中級（第1回・第3回を終えた方向け）
💡 この回の考え方：「起票は自動、判断は人。その間に“AIのレビュー”を挟む」
自動化が進むほど、怖いのは「間違いに気づかないまま積み上がること」です。だから畠山の本番運用では、起票のあとに必ずチェックの工程を置いています。今日渡す観点表は、その本番から抜き出したサンプル（土台）です。一定レベルまでは畠山が用意しました。ここから先は、皆さんの実務の「ヒヤッとした1件」を持ち寄って、みんなで育てていきましょう。

配布キットを最新版にする 📦

⏱ 約10分 🤝 準備ステップ

配布資料はすべてGitHubの配布用リポジトリ（畠山式 配布用リポジトリ（haifuyou））にあります。教材は回を追うごとに更新されているので、まず手元のキットを最新版にしましょう。

📋 手順（すでにフォーク済みの方）
  1. GitHubで自分のフォーク（自分のアカウント名/haifuyou）のページを開く
  2. 「This branch is XX commits behind…」の近くにある「Sync fork」→「Update branch」を押す（これで自分のコピーが最新になります）
  3. ブラウザ版Claude Code（claude.ai/code）の方はここまででOK。セッション作成時に自分のフォークを選べば、最新の教材一式が開いた状態から始められます
  4. デスクトップ版の方は、手元のフォルダも最新にする：クローンで取り込んだ方はClaude Codeに「このフォルダを git pull で最新にして」と頼むだけ。ZIPで取り込んだ方は「Code」→「Download ZIP」で取り直して展開（この機会にクローンへの切り替えもおすすめ。第1回🎁のコピペ文で頼めます）
📋 手順（まだの方：GitHubアカウント作成〜受け取り）
  1. github.com/signup でアカウントを作る（無料。メール→パスワード→ユーザー名→確認コードの順）
  2. 配布用リポジトリ（haifuyou）を開き、右上の「Fork」→「Create fork」で自分のGitHubに複製する（＝受け取り完了）
  3. ブラウザ版はセッションでフォークを選ぶだけ。デスクトップ版はClaude Codeにクローンを頼む（コピペ文は第1回課題ページの🎁セクションへ）

※ くわしい画面つきの説明は第1回課題ページの🎁セクションにあります。

仕訳帳をAIにレビューさせる 🔍

⏱ 約20分 🚀 本番・今日の主役①

ここからが第5回の本丸です。自動で起票された帳簿を、AIに税理士の目でチェックさせます。使うのは、畠山が顧問先の月次レビューで実際に使っている観点から抜き出したサンプル10観点です。

💡 レビュー観点（畠山サンプル・月次チェック10観点）
#観点何に気づける？
1資産科目のマイナス残高（現金・預金・売掛金など）入力漏れ・二重計上・科目間違いのサイン
2現金残高が大きすぎる／動きが不自然レジ・小口の実態と帳簿のズレ
3同日・同額・同摘要の重複仕訳明細とレシートの二重登録（freeeは消込APIがないため起きやすい）
4売掛金の滞留（3ヶ月以上消込がない相手先）回収漏れ・請求漏れ・消込忘れ
5科目ブレ（同じ相手先が月によって違う科目）ルール表に穴がある証拠。ステップ⑤の材料に
6期ズレ（計上月と取引月の食い違い、決算期またぎ）月次の損益が歪む。決算時の修正候補
7役員貸付金・仮払金・仮受金の残高滞留精算漏れ。決算までに整理すべき科目
8雑費の使いすぎ（経費に占める割合が高い）科目を決めきれていない仕訳のたまり場
9飲食系の科目と金額基準の不一致（1万円以下＝会議費／超＝交際費 など自社ルールとの照合）交際費の損金限度の管理ミス
10報酬支払と源泉所得税（外注報酬・士業報酬で預り金が立っているか）源泉徴収漏れ（納付漏れは加算税のもと）

※ 9の金額基準は畠山事務所の運用例です。自社・自事務所のルールに合わせて書き換えて使ってください。

📋 デスクトップアプリに貼るだけ：仕訳帳レビュー（観点はそのまま入っています）
freee MCPを使います。最初に、いま接続されている事業所名を確認して見せてください。
私が「その事業所でOK」と言ってから、次に進んでください。

OKと言ったら、今月（私が別の月を指定したらその月）の仕訳・試算表を取得して、
次の10観点で月次レビューをしてください。

1. 資産科目（現金・預金・売掛金など）にマイナス残高がないか
2. 現金残高が不自然に大きくないか・動きが不自然でないか
3. 同日・同額・同摘要の重複仕訳がないか
4. 売掛金で3ヶ月以上消込のない相手先がないか
5. 同じ相手先の仕訳で、月によって勘定科目がブレていないか
6. 計上月と取引の月がズレていそうな仕訳がないか（期ズレ）
7. 役員貸付金・仮払金・仮受金に滞留している残高がないか
8. 雑費が経費全体に対して多すぎないか
9. 飲食系の仕訳が金額基準（1万円以下=会議費／超=交際費）と合っているか
10. 外注報酬・士業報酬の支払で、源泉所得税の預り金が立っているか

結果は観点ごとに「判定（OK／要確認）／該当仕訳（日付・摘要・金額）／
そう判断した理由」の表にして、要確認の分だけ最後にまとめ直してください。
レポートは「事実 → 解釈 → 確認事項」の順で、
月次レビュー_YYYYMM.md というファイルに保存してください。

大事なルール：
- あなたは「気づき」を挙げる係です。正しいかどうかの税務判断はしないでください
- 修正はまだ実行しないでください。直し方の提案までにとどめて、
  私が「この仕訳を直して」と指定したものだけ、1件ずつ直してください
💡 MF会計の方は
1行目を「MF会計（マネーフォワード クラウド会計）のMCPを使います」に変えるだけで、同じ観点でレビューできます。仕訳帳をCSVでエクスポートして、そのファイルをClaude Codeに読ませる方法でもOKです（会計ソフトを問わない、いちばん汎用的なやり方です）。
🔒 安全メモ
  • レビュー結果のファイル（月次レビュー_YYYYMM.md）には取引先名や金額が入ります。GitHubのフォークにアップロードしない・掲示板に貼らないでください
  • 「要確認」は「間違い」ではありません。最終判断はあなた（人）です。AIの指摘を鵜呑みにして一括修正させないでください
🛠 迷ったとき・トラブル
  • 取得できる仕訳が少ない・ゼロ → 対象月を明細がある月に変えて指定してください。テスト事業所で試している方は、先にステップ②で数件起票しておくとレビューの練習になります。
  • 観点5（科目ブレ）が大量に出る → それが正常です。ルール表が育っていない証拠なので、ステップ⑤でルール化する材料にしてください。
  • 要確認が多すぎて読みきれない → 「要確認のうち、金額が大きい順に5件だけ詳しく説明して」と絞り込めばOKです。
  • レポートのファイルが見つからない → Claude Codeアプリのファイル一覧（サイドバー）で「月次レビュー」で探してください。
✅ このステップは完了済み（グレー表示）。読み直しはそのままどうぞ／戻すときは下のチェックを外してください

消費税区分をAIにレビューさせる 🧾

⏱ 約20分 🚀 本番・今日の主役②

科目が合っていても、消費税区分が間違っていると申告の数字がズレます。しかも税区分の間違いは画面上で目立たないので、人の目だけでは拾いきれません。ここもAIに点検の型を渡します。使うのは、畠山が実際の点検で使っているサンプル6観点です。

💡 税区分レビュー観点（畠山サンプル・6観点）
#観点よくある間違い
1少額特例の適用漏れ（税込1万円未満の課税仕入）インボイスなし（80%控除）のままになっている。要件を満たせば全額控除にできる
2海外SaaSの区分（Claude・ChatGPT・Zoom・Canva等）国内の課税仕入として処理している。登録国外事業者かどうかで扱いが変わる
3軽減税率8%の誤用飲食料品・定期購読新聞以外に8%が付いている（逆に、会議のお茶菓子が10%になっている）
4免税事業者への支払（登録番号のない相手）適格（100%控除）で処理している。経過措置（80%→50%）の区分にすべきもの
5非課税と対象外の混同土地の賃料・保険料・利息（非課税）と、海外取引・給付金・保険金収入（対象外）がごちゃまぜ
6売上側の区分課税売上10%になっているか。値引き・返金が「課税売上のマイナス」でなく課税売上返還で処理されているか

※ 少額特例には「基準期間の課税売上高1億円以下（または特定期間5千万円以下）」などの適用要件があります。要件を満たすかの判断は必ず人が行ってください（適用期限は2029年9月末までです）。

📋 デスクトップアプリに貼るだけ：消費税区分レビュー
freee MCPを使います。最初に、いま接続されている事業所名を確認して見せてください。
あわせて、この事業所の税込・税抜の設定と、消費税の課税方式（原則・簡易・2割特例など）が
分かれば教えてください。私が「OK」と言ってから、次に進んでください。

OKと言ったら、直近3ヶ月（私が別の期間を指定したらその期間）の取引を取得して、
消費税区分を次の6観点で点検してください。

1. 税込1万円未満の課税仕入で、インボイスなし（80%控除）の区分のままのもの
   （少額特例を使えば全額控除にできる可能性がある。ただし適用要件の判断は私がする）
2. 海外SaaS（Claude、ChatGPT、Zoom、Canvaなど）の支払が
   国内の課税仕入として処理されていないか
3. 軽減税率8%が飲食料品・定期購読新聞以外に付いていないか
4. 登録番号のない相手（免税事業者と思われる相手）への支払が
   適格（100%控除）で処理されていないか
5. 非課税（土地賃料・保険料・利息など）と対象外（海外取引・給付金など）が
   混同されていないか
6. 売上側の区分は正しいか（課税売上10%か、値引き・返金の処理が適切か）

結果は「観点／該当取引（日付・摘要・金額・いまの税区分）／
提案する税区分／理由」の表にして、税区分レビュー_YYYYMM.md に保存してください。

大事なルール：
- 一括修正はしないでください。私が内容を確認して「この取引を直して」と
  指定したものだけ、1件ずつ修正してください
- 適用要件の判断（少額特例が使えるか等）や、迷う論点は
  「確認事項」として私に残してください。税務判断はあなたの仕事ではありません
💡 MF会計の方は
1行目を「MF会計のMCPを使います」に変えて、税区分はfreeeのコード番号ではなく名称（課税仕入10%・軽減8%・非課税・対象外など）で指示してください。観点は同じです。
🔒 安全メモ
  • 税区分の修正は消費税申告の数字に直結します。体験の段階では、テスト用の事業所や自分の事業所で試してください。顧問先の本番データを直すときは、必ず修正前後の一覧を残してください
  • AIの提案は「候補」です。少額特例の適用可否・免税事業者かどうかの確認・迷う論点の結論は、人（税理士）の仕事です。事務所職員の方は所内の税理士に確認してから直してください
🛠 迷ったとき・トラブル
  • 該当がゼロで手応えがない → まずは正常ということです。「観点2だけ、判定の根拠になった取引を全部見せて」のように、OK判定の根拠を確認する練習をすると精度の感覚がつかめます。
  • 取引が多すぎて途中で止まる → 期間を1ヶ月に絞る、または「金額の大きい順に50件だけ」と上限を付けてください。
  • 登録番号のあり・なしが分からない → freeeの取引先設定（インボイス登録番号）を確認するようAIに頼むか、国税庁の公表サイトで検索してください。
  • 直した結果が合っているか不安 → 修正した取引の一覧を出させて、顧問税理士・所内の税理士とレビューしてください。この「人の最終チェック」までが型です。
✅ このステップは完了済み（グレー表示）。読み直しはそのままどうぞ／戻すときは下のチェックを外してください

ルールと観点に「自分の1行」を足す 🌱

⏱ 約15分 🌱 みんなで育てる課題

今日渡した観点表は、あくまで畠山のサンプル（土台）です。畠山の本番ルール表が15行から約700キーワードに育ったのと同じで、レビューの観点も「実務でヒヤッとした1件」をルール化する繰り返しで育ちます。ここからは皆さんの番です。

📋 手順：今日の気づきを1行にする
  1. ステップ③④の「要確認リスト」から、自分の実務ならではの1件を選ぶ（科目ブレでも、税区分の癖でも、業種特有の取引でもOK）
  2. それをルール化する。下のコピペ文をClaude Codeに貼れば、どのファイルにどう書くかまで手伝ってくれます
    • 科目の判定ミス → scripts/rules.csv か 勘定科目ルール.md に1行追加
    • チェックの観点 → 自分用の「レビュー観点メモ」に1個追加（③④のプロンプトに足して使う）
  3. （クローンで取り込んだ方・任意）Claude Codeに「この変更を自分のフォークにコミットしてプッシュして」と頼むと、育てたルールが自分のGitHubに保存されます。コミットするのはルールの行だけ（帳簿データやレビュー結果は含めない）
📋 デスクトップアプリに貼るだけ：気づきをルール化する
今日の月次レビューで見つかった「要確認」の中から、
ルール化する価値がありそうなものを一緒に選びたいです。

まず、要確認リストを「毎月起きそうか／金額が大きいか／
ルール化すれば次から自動で防げるか」の3つの目線で並べ直してください。

私が1件選んだら、
- 勘定科目の判定に関するもの → scripts/rules.csv（または勘定科目ルール.md）に
  追加する1行の案を作って、私がOKしたら追記してください
- チェック観点に関するもの → 「マイレビュー観点.md」というファイルに
  観点として1行追加してください（観点／何に気づけるか／判定の目安 の形式で）

追記が終わったら、追加した1行を「恩送りメモ用」に、
顧問先名・取引先名・具体的な金額が分からない形に言い換えて出力してください。

❓ よくあるつまずき

顧問先の本番データでやってもいい？
レビュー（見るだけ）は本番データでも大きな事故は起きにくいですが、修正は必ず1件ずつ・内容を確認してからにしてください。最初はテスト用の事業所か自分の事業所で型に慣れて、それから本番に広げるのが安全です。修正前後の一覧を残すのも忘れずに。
AIのレビュー結果は信じていいの？
AIの指摘は「気づきの候補」です。見落としを拾う網としては優秀ですが、直すかどうかの判断（税務判断）は人の仕事です。畠山の本番運用でも、AIの所見は必ず人が最終確認してから反映しています。この「AIが網を張り、人が判断する」分担こそが今日の型です。
少額特例ってなに？
税込1万円未満の課税仕入なら、インボイス（適格請求書）の保存がなくても全額を仕入税額控除にできる特例です（2029年9月末まで）。ただし基準期間の課税売上高1億円以下（または特定期間5千万円以下）という適用要件があります。自社が要件を満たすかの判断は、必ず人が確認してください。
MF会計でも同じことができる？
できます。ステップ③④のコピペ文の1行目を「MF会計のMCPを使います」に変えて、税区分はコード番号ではなく名称で指示してください。また、仕訳帳をCSVでエクスポートしてClaude Codeに読ませる方法なら、どの会計ソフトでも同じ観点でレビューできます。
追加した1行は共有しないとダメ？
共有は恩送りメモの形でお願いしています（修了条件）。ただし抽象化した形でOKです。顧問先が特定される情報・具体的な金額は入れないでください。良い観点は配布キットに取り込んで、次回の配布で全員に還元します。

何回でも再挑戦できます。70点未満のときは、Claudeが間違えた所をやさしく解説してから別の問題を出してくれます。テストは「できなかった探し」ではなく、今日の体験を自分の言葉にするための仕上げです🌸
